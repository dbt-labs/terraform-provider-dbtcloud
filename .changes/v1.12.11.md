# [v1.12.11](https://github.com/dbt-labs/terraform-provider-dbtcloud/compare/v1.12.10...v1.12.11)
### Changes
* Add `private_key_wo` and `private_key_wo_version` to the `bigquery` block of `dbtcloud_global_connection`, a write-only alternative to `private_key` that is not stored in the Terraform state (requires Terraform >= 1.11)
### Fixes
* Make `dbtcloud_notification_setting` deletion idempotent: a 404 from the delete API is now treated as success instead of failing the apply (#718).
* environment resource's Delete now treats a 404 (already deleted) as success instead of failing terraform apply
* environment resource's Read now treats a 404 (already deleted) as success instead of failing terraform plan/destroy, matching the existing Delete behavior
* `dbtcloud_partial_notification` with `notification_type = 5` (Slack V2) now matches existing notifications by `slack_channel_id`, instead of adopting (and overwriting the channel of) the first Slack V2 notification in the account
* `dbtcloud_partial_notification` with `notification_type = 5` (Slack V2) now updates `slack_channel_name` in place instead of destroying and re-creating the notification, since Slack V2 notifications are identified by `slack_channel_id` only
* send private_key_wo, password_wo and private_key_passphrase_wo on dbtcloud_snowflake_semantic_layer_credential, which were dropped and left the credential without a key
* send writable_environment_categories = ["all"] on dbtcloud_service_token instead of dropping it, which left the token with no environment write access
* keep the configured order of dbtcloud_webhook job_ids, which made every apply fail when the API returned them in another order
* stop dbtcloud_postgres_credential planning an update on every run when password_wo is used
* stop imported jobs, projects and postgres credentials from showing a difference that no configuration can express
* Stop `dbtcloud_auth_provider` from resetting the Auth0 migration status on update, and expose it as `use_auth0`
### Behind the scenes
* run the write-only credential acceptance tests, which were skipped for a Terraform version requirement that CI has met for some time
* Add a `write-only-attributes` skill and a doc comment on `helper.ResolveWriteOnlyString` documenting the pitfalls of write-only (`_wo`) attributes, and link `.claude/skills` to `.agents/skills`
### Documentation
* Update the resource relationships guide: split the diagram, which had drifted out of date, into four diagrams by area (account & access, connections & credentials, project & environment, jobs & orchestration)
* Document the Account Admin permission that `dbtcloud_model_notifications` needs
