# [v1.12.13](https://github.com/dbt-labs/terraform-provider-dbtcloud/compare/v1.12.12...v1.12.13)
### Changes
* add the `dbtcloud_analytics_credential` resource and the analytics credentials API client
* add the `analytics_connection_id` attribute on the `dbtcloud_project` resource and on the `dbtcloud_project` and `dbtcloud_projects` data sources
* add the read-only `analytics_credentials_id` attribute on the `dbtcloud_global_connection` resource and on the `dbtcloud_global_connection` and `dbtcloud_global_connections` data sources
* accept the `v1-` and `v2-` spellings of the dbt release tracks (`v1-latest`, `v2-stable`, ...) for `dbt_version` on `dbtcloud_environment` and `dbtcloud_job`, treat `v2-` tracks as Fusion, and stop showing a diff when the configured and stored values are two spellings of the same version, including after importing a `dbtcloud_environment`
### Fixes
* Removing the `ssh_tunnel` block of a `dbtcloud_global_connection` no longer fails when the server has already removed the tunnel
### Behind the scenes
* Build with Go 1.26.10, which blocks the compromised emSign (eMudhra) intermediate certificates
### Documentation
* clarify in the `dbtcloud_environment` docs and schema that `connection_id`, `credential_id` and `extended_attributes_id` belong to the profile and should be managed through `dbtcloud_profile` when `primary_profile_id` is set
